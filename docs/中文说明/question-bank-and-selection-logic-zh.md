## 三、每次检查的出题逻辑（算法）

```
┌─────────────────────────────────────────────────────────────┐
│  1. 必答安全筛查  rf1–rf5 · w1 · sk1                 7 题    │
│     （永远最先问，无法排除急症时系统会「安全弃权」）          │
├─────────────────────────────────────────────────────────────┤
│  2. 个性化抽取    4 题（见下方 4 步算法）                    │
├─────────────────────────────────────────────────────────────┤
│  3. 条件分支      满足触发条件才追加（0–4 题）                │
└─────────────────────────────────────────────────────────────┘
        每次实际题量 ≈ 11 题（触发分支后最多约 15 题）
```

### 第 2 步：4 道个性化题是怎么选出来的

1. **资格过滤（appliesIf）** — 从题库里剔除「必答题」和「条件分支题」，只留下对该用户**适用**的题目。
2. **相关度排序（relevance）** — 在**每个分类内部**，按个人资料给每题打分（年龄、病程、HbA1c、吸烟、合并症、穿鞋、赤脚、护理习惯、截肢史）。得分 >0 的「相关题」永远排在前面。
3. **轮换（rotation）** — 把每个分类里的「相关题」和「其余题」分别用种子 `seed` 旋转，所以**具体问到哪一道会变化**，但一定优先考虑最相关的候选。
4. **轮询取题（round-robin）** — 按「相关度最高的分类优先」的顺序，**每个分类轮流取 1 题**，直到取满 4 题。这样保证一次检查能**覆盖不同临床领域**，而不是集中在某一类。目前可轮换的分类正好 4 个（神经、皮肤、循环、病史），所以**每次检查这 4 个领域各出 1 题**，逐次只更换「具体哪一道」。

### 种子（seed）：怎么保证「每次不一样」

```
seed = 当天日期序号 × 1000 + 当天第几次检查
```

| 场景 | 结果 |
| --- | --- |
| 同一天、同一次检查内 | 题目**稳定不变**（老人不会中途看到题变） |
| 同一天、重新做一次检查 | 抽到**不同的** 4 道个性化题 |
| 不同的一天 | 再次**变化**（满足「不一定每天一样」） |
| 相同资料 + 相同 seed | **完全可复现**（结果可审计、可解释） |

### 关键设计取舍

- **为什么 7 题必答？** 这 7 题是安全底线：5 个红旗症状 + 伤口状态 + 皮肤检查，直接决定「该不该马上去急诊」。若跳过，系统就无法排除严重感染，只能保守地「安全弃权」。
- **同类题不会在一次检查里重复**：轮询取题保证**每个临床分类最多出 1 题**，所以即使题库里同一分类有多道相近题（如 n2 与 n4），老人同一次也不会被重复追问。
- **性别是否参与出题？** 个人资料**采集**性别，但**不**用它来筛题或加权。因为 IWGDF / NICE 的风险分层**并不按性别**区分足部风险；把它排除在外是刻意的**公平性**设计（本项目含公平性测试能力）。
- **个性化 vs 安全**：个性化只影响「非关键问题」；关键安全题永远固定，保证不漏诊。
